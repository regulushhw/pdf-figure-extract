# 复杂位图：柱体/区间线与曲线身份候选

两个模块已接入固定入口，仍为试验方法，不默认替代已有清晰图的读取器。图例、统计量、零线、面板与系列由Agent按原文确认；程序判断的是几何候选，不保证自动理解研究身份。输出统一接inspect/edit/undo，不另建纠错或写表流程。

## 柱体、有帽区间与无帽区间

局部纠错时可用对象的 `review_roles` 声明本次对应表格的角色。程序仍分析完整图元，完整候选留在几何证据中，只有本次声明的角色进入改点队列和工作表对账。

扫描图精读先保留原始像素，再看候选回叠图。扫描倾斜使同一面板的零线随横坐标变化时，在实际轴线或柱底拟合零线，再换算柱高；标定不使用待比较的表格结果反向调参。图表合计与正文/原表不一致时分别保留来源，记录差值，不修改读数来凑表值。

同一细竖线上只看见两个横帽，不证明第三个横帽在中点，也不能确定隐藏值与哪一端重合。横帽候选须排除标题数字、历史柱边和坐标轴，并查看其与目标竖线的连接；只确认清晰可见的点。被遮挡的中间值或按端点平均所得值仍属估计，不能因数值合理就升级为读图值。原图未编码年代顺序时，可按高/中/低记录，但不能赋予具体十年身份。


固定方法`bitmap_bar_ranges`，脚本`tools/complex_bars.py`。使用现有NumPy/Pillow和OpenCV形态学；OpenCV是可选依赖，见requirements-complex.txt，不在任务运行中自动安装。

箱线图沿用同一方法，配置 `boxplots`。每个箱填写 `id`、`panel`、`identity`、`roi`、中心 `x` 和从中心到箱边的原图像素距离 `box_half_width`。槽位应避开图例和相邻箱，包含预期须线。程序检验箱内三条横线和两侧的连通性，再寻找与箱体连通的短横帽。默认覆盖 `q3`、`median`、`q1`、`upper_whisker`、`lower_whisker`，可用 `review_roles` 指定任务要求的统计量。须线断开或存在多个候选时进入复核。此配置使用标定后的纵轴，无需零线。

箱线任务使用分类横轴时，在 `gate_axes.x` 记录类别中心的原图像素位置及独立复查位置，`identity.x` 填写对应类别。程序以相邻类别中心的中点划分各组。组内箱可以偏离类别中心，但取数区域必须完整落在所属类别内。

箱边、中位线和须线颜色不同时，`selector` 选箱边，另外配置 `median_selector` 与 `whisker_selector`。三者都以原图为准，可按图或按槽位配置。对抗锯齿颜色可用 `{"mode":"dominant_channel","channel":"blue","margin":81}`，表示蓝色通道至少比另两通道各高 81。须线为黑色时可用 RGB 距离筛选。颜色与角色须由图面确认，贴轴的须线仍保留复核标记。

```json
{
  "sources":{"s":{"image":"source.png"}},
  "panels":{"p":{"source":"s","bounds":[1,1,198,198],"zero_y":90,
    "axis":{"coordinate":"y","ticks":[[40,50],[90,0],[140,-50]],"unit":"%"}}},
  "bars":[{"id":"bar1","panel":"p","identity":{"series":"2020s","statistic":"median"},
    "x":45,"roi":[35,10,55,180],"range_expected":true}],
  "capped_ranges":[{"id":"base1","panel":"p","identity":{"statistic":"baseline ensemble range"},
    "roi":[10,10,30,180],"crosses_zero":true}]
}
```

每根柱提供已经确认的x位置与槽位ROI，不默认等距或按大小排系列；零线须明确。槽位应包含自身边框，避免截掉网纹柱外边缘或包含相邻柱。可用selector选择灰度/颜色及exclude_boxes排除图例。`range_expected=false`只用于原图确实不含区间线的柱，不以此隐藏未读端点。

空心/网纹柱可显式配置`fill_outline_max_width`（2—40源像素）。它仅为柱体支撑填充窄且闭合的背景孔洞，不填宽阔绘图区或开口轮廓；须线/横帽仍读原掩膜。默认不启用。无须线柱图采用包含目标列的连续横向宽度判定，允许柱中心略偏向柱边；有须线图仍保留对称两侧支撑以排除细竖线。近零、断口和两侧候选继续留歧义或缺值。

柱位有累积偏差时，可选`bar_groups`，每项提供panel、left/right及按横向顺序列出的groups二维ID清单；必须明确`within_group="equal_width"`。程序在零线上下的`probe_offsets`带（默认4—7源像素）联合找实际组边界，复用既有locate_bar_groups，再按声明的组内等宽条件分槽。`join_px`默认5，须小于组间空白；`min_group_width`默认24；可设min_bar_width/max_bar_width检查组宽。数量/宽度不符直接失败，不自动放宽阈值；同组ID须同面板、选择器/排除区一致，且已确认不含须线。它不识别图例、不按柱高重排身份。原柱位、检测边界与新槽位留在geometry.json，选择器掩膜按来源及排除区复用。

程序分开处理：

- 柱体要求中心线两侧都有墨迹，避免把单根竖线当柱。网纹柱的连通判断使用小范围闭运算；这只影响柱体候选，端点与横帽始终读原始掩膜。近零、两侧都有柱体或未找到时保留歧义/空候选，不填0。
- 竖线按原始墨迹段检测，横帽用水平形态学检测并检查是否跨过竖线；相邻描边列合并为同一几何候选。重复配对保留，不任取一条。
- 有帽区间要求两端均有横帽；若原文说明基准范围跨零，可显式要求crosses_zero。缺帽、相邻柱边框或图例装饰可能造成歧义，不能仅凭形状自动指定统计含义。
- 无帽竖线与已分配柱的中心/柱体相交关系用于配对；端点与柱顶/零线重合，或端点检测到横帽时留空并送核对。

输出角色：bar_tip、uncapped_top/bottom、capped_top/bottom。**top/bottom是图像y坐标的上/下端，不是数值大小顺序**；geometry.json另存标定后的候选值。语义上的基准/未来范围及分位数必须沿用图注。不同面板不能混用区间定义。

两个帽端共享横帽，且竖线在两端之间的三个位置都有连续横向墨迹时，粗竖线的相邻像素列合为一根。输出保存参与的源列。平行且彼此分离的竖线仍为不同候选。

扫描偏斜、各柱底部的像素高度不完全相同时，可在面板填 `body_baseline: [[x1,y1],[x2,y2]]`，两点取同一条底边，并夹住柱子的横坐标。只对已声明无区间线的柱形用这一配置。它用于寻找柱体与底边的接触位置，换算仍用图卡的轴标定。

无帽区间竖线在扫描图上从上到下偏离同一列时，可在该柱上填 `stem_guide: [[x1,y1],[x2,y2]]`。两点取同一根可见线身的原图像素，按 Y 递增排列。程序沿线身找端点，返回实际源图坐标。端点落在柱体内部、柱顶或零线附近时，保留几何证据和复核标记。只有端点与这些墨迹能分开时，才给自动候选。

## 密集、交叉、重叠与虚线曲线

**相邻柱可能粘连**：形态学操作可能把网纹柱与相邻实心柱合并。检查相邻柱、图例和实际端点；近零、接触或候选同高的位置尤其需要回图确认。

固定方法`bitmap_curve_identity`，脚本`tools/complex_curves.py`。每个系列明确选择器、至少两个锚点、线宽范围与实/虚线；不会按纵向高低重命名情景。

可在系列配置中用 `"auto_anchors": true` 替代 `anchors`。程序在取样范围内，选取只有一段墨迹符合该系列宽度、且邻列有连续证据的位置作首末锚点。这个模式可直接处理不超过 2,000 万像素的来源选区。选区仍须能代表目标系列。缺足够锚点或虚线轨迹缺少断续证据时，保留取样格和复核标记。原有显式锚点方式继续可用。

自动追踪中断时，从另一端反向追踪并保留两端实际墨迹上的候选。未连通处继续留缺。单侧候选和两向落点有分歧的位置进入复核。

可用 `min_component_span_px` 和 `max_component_span_px` 按连通笔画的横向长度过滤候选，保留原像素坐标。连续灰线可用下限去掉短碎片。虚线有短划证据时可用上限排除过长的连通笔画。启用 `interpolate_dash_gaps` 时，程序只在两侧都有墨迹、且观测间隙在长度限制内的位置插值，并记录两侧像素供复核。

`axis_rule_rows` 仅提供需要检查的原像素行号。程序报告附近横贯图区的笔画和相关待核点，读数掩膜保留原有墨迹。水平形状或靠近零刻度都不足以认定参考线。结合图例、标注和原图判断水平笔画的身份。

```json
{
  "sources":{"s":{"image":"source.png"}},
  "panels":{"p":{"source":"s","bounds":[1,1,198,198],
    "axis":{"coordinate":"y","ticks":[[20,100],[180,0]],"unit":"Ml/d"}}},
  "traces":[{"id":"curve1","panel":"p","identity":{"series":"scenario"},
    "roi":[5,5,190,190],"anchors":[[10,40],[180,150]],"sample_x":[10,50,100,150,180],
    "selector":{"mode":"gray","range":[0,180]},
    "style":{"pattern":"dashed","width_range":[1,3],"max_gap_px":8},
    "beam_width":32,"max_step_px":10,"anchor_tolerance_px":2,"slope_weight":1.5,"ambiguity_cost":1.0}]
}
```

带上下文的线宽、颜色与线型仍需原图图例确认；锚点不可直接抄待验证位置的答案。ROI最多300000像素，beam最多128，gap最多30像素。形态超出范围时拆面板，不无限扩大搜索。

- 有界多假设搜索结合斜率变化、线宽及锚点约束保留备选。宽度惩罚和路径成本不是置信概率；最平滑路径不一定是目标曲线。
- 同一列的连续墨迹宽于预期线宽时，搜索保留墨迹中心和沿进入方向延续的候选。宽墨迹内的落点携带原图纵向范围，并进入身份复核。已给定的锚点仍约束路径，完全可分辨的窄墨迹仍按中心取点。
- 实线附近有可用墨迹时不为降低成本主动跳过；虚线允许有限断口，但断口保持缺值，不能把预测连线作为读图值。虚线身份需要源图中有断口支持，算法自行跳过墨迹不算依据。
- 多系列轨迹接近/共享同一墨迹时进入身份核对；输出重合候选不能证明实际数值相等，完全遮挡处不能恢复隐藏差异。
- 多系列接近时，候选证据同时记录连续源像素区段及相邻系列，方便按区段核对。位图候选沿用固定入口、原图叠图及编号点复核。
- 同一采样列的两个已观测笔画范围有交集时，复核结果列出共同像素范围及另一条轨迹的标识。局部插值和只在附近走过的轨迹不给出共同像素范围，填写共同约值仍要复核两条系列的身份。
- 确认共同约值时，两点须在同一批原图复核中用 `accept` 分别确认，并在两项操作上各用 `confirm_shared_with` 指向对方的点 ID。程序检查二者使用同一原图像素且该像素落在观测交集内。证据随两个单元格保留，后续改动其中任一个点会解除这项共同确认。
- 审阅稿须同时绑定两条相互确认的读数。交付关卡核对共同落点、原始读数和笔画范围一致。
- 确认图例为虚线、能在原图量出孤立短划的跨度时，可给轨迹设 `dash_fragment_span_px`。程序复用同一追踪器独立追短墨迹，并核对起始锚点。短墨迹支持的备选写入点级证据，叠图中以蓝色示出；与原追踪不一致的点仍进入复核。虚线间的局部插值须显式开启 `interpolate_dash_gaps`，保留两侧墨迹坐标。没有短墨迹支持的原路径会标记，而不会当成已确认的虚线。
- 断续点线的陡峰可能离开整段追踪路径。同一采样列上的孤立短墨迹另作备选，进入局部原图复核。此类备选提供实际像素，系列身份由图例、前后线型和原图核对。
- 图例明确区分点线和长虚线时，可用 `style.pattern: "dotted"` 读点线。点线默认不惩罚相邻墨迹间的方向变化，允许保留陡峰，仍受线宽、最大步幅、缺口与锚点约束。`dash_fragment_span_px` 同样适用。图例为长虚线时仍选 `dashed`。
- 横笔画已由原图刻度和重复网格证实为网格线时，可在 `confirmed_grid_rows` 逐行记录 `row` 与 `reason`。程序回查这行墨迹至少跨过读数区的 80%，只在追踪副本中屏蔽，并保留完整原图。屏蔽后仍无落点的位置需要查看原图是否与网格重叠。
- `geometry.json` 的 `horizontal_review_candidates` 自动列出横笔画的像素行、覆盖比例、纵轴读数及邻近的已核刻度。候选也可能是水平数据线，须先按图面证据确认才填入 `confirmed_grid_rows`。
- 同一列远处还有其他曲线，不会单独触发复核；附近分支、线宽冲突、共享墨迹、多个路径和缺口仍标记。无告警也不是已核验。

## 运行与证据

```text
python tools/complex_bars.py job.json 新输出目录
python tools/complex_curves.py job.json 新输出目录
```

日常在task.json的part选择相应固定方法，通过run_task的trial→确认→run→inspect/edit/undo。生成器可使用已有job/trial_job对象，不声称已提供这两种方法的紧凑参数模板。旧有清晰实线仍优先原bitmap_lines；不要因增加新模块就重做已有效的取点。

共同输出source_job.json、来源图摘要、geometry.json、review_job.json、检查叠图和短摘要。缺值/多候选按原接口拦截保存；图义、单位和出处仍要核对。看图属于同一Agent自检，程序通过不代表整图完成。

验证：tests/test_complex_geometry.py用已知合成图检验正负柱、薄竖线与柱体区别、帽线配对、区间位于零线一侧、交叉/共享墨迹、虚线缺口及固定入口。复杂图元模块提供候选，不保证自动完成所有曲线身份与端点配对。

OpenCV复用依据：[官方形态学分离水平/竖直线教程](https://docs.opencv.org/4.13.0/dd/dd7/tutorial_morph_lines_detection.html)。本项目几何配对和多假设搜索为原有工具的新增实现，不宣称调用了第三方完整图表理解模型。
